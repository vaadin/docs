= Listening to Element Events

The Element API contains methods to receive events and event data from the browser and handle them on the server side.


== Registering Event Listeners

Use the [methodname]`Element.addEventListener()` method to listen to any browser event.

.Using the [methodname]`addEventListener()` method to react to a `click` event
[example]
====
[source,java]
----
Element helloButton = ElementFactory.createButton("Say hello");
helloButton.addEventListener("click", e -> { // <1>
    Element response = ElementFactory.createDiv("Hello!");
    getElement().appendChild(response); // <2>
});
getElement().appendChild(helloButton);
----
<1> Clicking the "Say hello" button in the browser sends the event to the server for processing.
<2> A new `<div>Hello!</div>` element is added to the DOM.
====

== Accessing Data from Events

You can get more information about the element or user interaction by defining the required event data on the [classname]`DomListenerRegistration` returned by the [methodname]`addEventListener()` method.

.Using the [methodname]`addEventData()` method to define the required event data
[example]
====
[source,java]
----
helloButton.addEventListener("click", this::handleClick)
    .addEventData("event.shiftKey") // <1>
    .addEventData("element.offsetWidth");

private void handleClick(DomEvent event) {
    JsonNode eventData = event.getEventData(); // <2>
    boolean shiftKey = eventData
            .get("event.shiftKey").asBoolean(); // <3>
    double width = eventData
            .get("element.offsetWidth").asDouble();

    String text = "Shift " + (shiftKey ? "down" : "up");
    text += " on button whose width is " + width + "px";

    Element response = ElementFactory.createDiv(text);
    getElement().appendChild(response);
}
----
<1> The requested event data values are sent as a JSON object from the client.
<2> You can retrieve the event data using the [methodname]`DomEvent.getEventData()` method in the listener. It returns a Jackson [classname]`JsonNode` (from `tools.jackson.databind`).
<3> Look up each value by the same key you passed to [methodname]`addEventData()`, then read it with the accessor that matches its type -- for example [methodname]`asBoolean()`, [methodname]`asInt()`, [methodname]`asDouble()`, or [methodname]`asText()`.
====

.Return Type Changed from Elemental JSON
[NOTE]
[methodname]`DomEvent.getEventData()` now returns a Jackson [classname]`JsonNode` (`tools.jackson.databind.JsonNode`) instead of the previous Elemental `JsonObject`. Code written for earlier versions no longer compiles: replace `JsonObject` with [classname]`JsonNode`, and the Elemental getters such as `getString(key)`, `getBoolean(key)`, and `getNumber(key)` with `get(key).asText()`, `get(key).asBoolean()`, and `get(key).asDouble()`. See <<{articles}/upgrading#,the upgrade guide>> for the full list of Elemental-to-Jackson changes.

The browser compiles each [methodname]`addEventData()` expression from a string, so it doesn't work with a Content Security Policy that doesn't allow `unsafe-eval`. To get event data under such a policy, declare it in a [annotationname]`@JsDefinition` interface as a method returning [classname]`DomEventData`, and pass what the method returns to [methodname]`addEventData()`.

.Declaring event data and reading it with [methodname]`getEventData(DomEventData)`
[example]
====
[source,java]
----
@JsDefinition
public interface ButtonEventsJs extends Serializable {

    @JsExpression("return event.shiftKey;")
    DomEventData<Boolean> shiftKey();
}

private static final ButtonEventsJs JS = JsSnippets.of(ButtonEventsJs.class);

private void addHelloButtonListener(Element helloButton) {
    DomEventData<Boolean> shiftKey = JS.shiftKey();
    helloButton.addEventListener("click", event -> {
        boolean shiftPressed = event.getEventData(shiftKey);
        // ...
    }).addEventData(shiftKey);
}
----
====

The build adds the declared expression to the frontend bundle, so the browser runs it without compiling anything from a string. See <<calling-javascript#declaring-javascript,Declaring JavaScript in Java>> for more about [annotationname]`@JsDefinition` interfaces.


== Filtering and Debouncing

Filtering and debouncing are covered in detail in <<../events#limiting-event-frequency,Declaring and Firing Component Events>>, in the context of the `@DomEvent` annotation. However, you can configure the exact same settings through the [classname]`DomListenerRegistration` object.

[methodname]`DomListenerRegistration.setFilter()` takes the filter as a JavaScript expression string, which the browser compiles, so it doesn't work with a Content Security Policy that doesn't allow `unsafe-eval`. To filter events under such a policy, declare the filter in a [annotationname]`@JsDefinition` interface as a method returning [classname]`DomEventFilter`, and pass what the method returns to [methodname]`setFilterExpression()`.

.Declaring a filter and using it with [methodname]`setFilterExpression()`
[example]
====
[source,java]
----
@JsDefinition
public interface KeyFiltersJs extends Serializable {

    @JsExpression("return event.key === $0;")
    DomEventFilter isKey(String key);
}

private static final KeyFiltersJs FILTERS = JsSnippets.of(KeyFiltersJs.class);

private void addSubmitOnEnter(Element field) {
    field.addEventListener("keydown", event -> submit())
            .setFilterExpression(FILTERS.isKey("Enter"));
}
----
====
