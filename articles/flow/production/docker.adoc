= Deploying Using Docker

A https://docs.docker.com/get-started/docker-overview/[Docker container] is a standalone, executable package of software that includes everything needed to run an application: code, runtime, system tools, system libraries, and settings. A [filename]`Dockerfile` contains the instructions for building the image that the container runs.

To build and run the image, you need https://docs.docker.com/desktop/[Docker Desktop] or https://docs.docker.com/engine/install/[Docker Engine].


== Building Inside Docker

Projects downloaded from https://start.vaadin.com[Vaadin Start] include a [filename]`Dockerfile` that runs the Maven build inside Docker. You don't need to build the application before building the image, and the machine that builds the image doesn't need Java.

To build the image and run it on port 8080, run the following commands in the project directory:

[source,terminal]
----
docker build -t my-app .
docker run -p 8080:8080 my-app
----

The [filename]`Dockerfile` has three stages:

. The first stage provides the `jq` tool, which the build stage uses to read a license key.
. The build stage uses an Eclipse Temurin JDK image, and runs `./mvnw clean package -DskipTests`, so the tests don't run. It keeps the downloaded Maven dependencies in a build cache between builds.
. The runtime stage uses an Eclipse Temurin JRE image based on Alpine Linux. It copies the JAR from the build stage, and starts the application with the `prod` Spring profile active.

The images are for the Java version that you selected on Vaadin Start. The application runs as the `root` user, with the default memory settings of the JVM.

The project contains no configuration for the `prod` profile. To add production settings, put them in [filename]`src/main/resources/application-prod.properties`. When the profile is active, Spring Boot reads this file in addition to [filename]`application.properties`, and its values take precedence.


=== Passing a License Key

If the build needs a license key, as described in <<{articles}/flow/configuration/licenses#,License Validation & Troubleshooting>>, pass the key file as a https://docs.docker.com/build/building/secrets/[build secret]. The secret is available only while the Maven build runs, and isn't stored in the image. The [filename]`Dockerfile` reads an offline key from a secret with the ID `offlineKey`, and a pro key from a secret with the ID `proKey`:

[source,terminal]
----
docker build --secret id=offlineKey,src=$HOME/.vaadin/offlineKey -t my-app .
----


== Building from a JAR

If you build the JAR outside Docker, for example on a CI server, a [filename]`Dockerfile` that copies the JAR into a Java runtime image is enough:

.`Dockerfile`
[source,dockerfile]
----
FROM eclipse-temurin:25-jre
COPY target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app.jar"]
----

This [filename]`Dockerfile` works for applications that are packaged as an executable JAR, such as Spring Boot applications. Use the image tag that matches the Java version of your project.

Make a <<production-build#,production build>> of the JAR first, then build and run the image:

[source,terminal]
----
mvn clean package
docker build -t my-app .
docker run -p 8080:8080 my-app
----

<<{articles}/building-apps/production/container#,Build a Container Image>> extends this [filename]`Dockerfile` with image layers, an unprivileged user, and memory settings for the JVM, and explains why each of them matters.

For all instructions that a [filename]`Dockerfile` can contain, see the https://docs.docker.com/reference/dockerfile/[Dockerfile reference].
