= React Views

A React view is a view written in React and TypeScript that runs in the browser. It calls Java code on the server through <<browser-callable-services#,browser-callable services>>, using a TypeScript module that Vaadin generates for each service. A Flow view, by contrast, runs on the server, and the browser only shows what the server sends it.

React views and Flow views can be in the same application. They share the client-side router and the browser session, and the same Spring Security configuration protects both.

This section is the reference for React views. For when to choose a React view, and for step-by-step guides, see <<{articles}/building-apps/react#,React Views>> in Building Apps.

== Enabling React Views

React views and browser-callable services come with the Hilla Spring Boot starter, which `vaadin-spring-boot-starter` doesn't include. Add it to the project:

.[filename]`pom.xml`
[source,xml]
----
<dependency>
    <groupId>com.vaadin</groupId>
    <artifactId>hilla-spring-boot-starter</artifactId>
</dependency>
----

The version comes from the `vaadin-bom` dependency management. Without the starter, Vaadin ignores the files in [filename]`src/main/frontend/views` and generates no TypeScript clients for services.

React views require a Spring Boot application.


== Frontend Files

React views and the files around them are in [filename]`src/main/frontend`:

[filename]`views/`::
The views. The router derives each view's route from its path in this directory. See <<routing#,Routing>>.

[filename]`generated/`::
Files that Vaadin generates when it builds the frontend. These include the TypeScript clients of browser-callable services, the route list, and the default [filename]`routes.tsx` and [filename]`index.tsx`. Vaadin overwrites them, so don't edit them.

[filename]`routes.tsx`, [filename]`index.tsx`::
Optional. Vaadin uses a file here instead of the generated one. To customize the router, start from a copy of the generated [filename]`routes.tsx`, as described in <<routing#routes-file,The Route Configuration File>>.


== React and Flow Views in One Application

The router shows a React view when one matches the path. Otherwise, it passes the path to the server, which shows the Flow view with that route. Links and programmatic navigation work the same way for both kinds of views.

Beyond navigation, the two kinds of views share these parts:

- *Menu*: the function that creates menu items from the React views also includes Flow views annotated with [annotationname]`@Menu`.
- *Layout*: a Flow layout annotated with [annotationname]`@Layout` can wrap React views.
- *Page title*: a React layout can show the page title of Flow views.

See <<flow-interop#,Flow Interoperability>> for these, and for using Flow components inside React views.
