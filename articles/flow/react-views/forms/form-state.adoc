= Form State
:toclevels: 2

The result of [methodname]`useForm()` describes the state of the form. The result of [methodname]`useFormPart()` describes the state of a part of the form, such as a single field. The component re-renders when the state changes.

section_outline::[]


[[properties]]
== State Properties

The form and its parts have these properties:

`value`::
The current value.

`defaultValue`::
The value that was last read or submitted.

`dirty`::
`true` when the value differs from the default value. A form stays dirty when the user changes a field back to its original value, because the form then has a new value object. A single field with a string, number, or boolean value compares the values themselves.

`visited`::
`true` when the field has lost focus at least once. It's only set for fields, not for the form or for parts that contain several fields.

`required`::
`true` when the field is required, as described in <<validation#required,Required Fields>>.

`invalid`::
`true` when there are validation errors.

`errors`::
The validation errors of the form or the part, including the errors of the fields that it contains. Each error has a `property`, which identifies the field by its model or its path, and a `message`. When a component reports its own input as invalid, for example because a required field is empty, the errors also contain an error with an empty message.

`ownErrors`::
The validation errors that belong to the form or the part itself, and not to a field that it contains.

The form also has a `submitting` property, which is `true` while the `onSubmit` callback runs. See <<index#submitting,Submitting>>.

For example, the following button is enabled only when there is something to save, and the list shows all the errors of the form:

[source,tsx]
----
const { model, field, dirty, submitting, errors } = useForm(PersonModel, {
  onSubmit: async (person) => {
    await PersonService.savePerson(person);
  },
});

// ...

<Button onClick={save} disabled={!dirty || submitting}>
  Save
</Button>
<ul>
  {errors
    .filter((error) => error.message)
    .map((error, index) => (
      <li key={index}>{error.message}</li>
    ))}
</ul>
----


[[changing-values]]
== Changing Values from Code

To change the value of a field from code, call [methodname]`setValue()` of its part, or of the form with a new value for the whole form. Don't change the objects in `value` directly: the form doesn't notice such changes, so it neither re-renders nor validates.
