= End-to-End Testing with Playwright

link:https://playwright.dev/java/[Playwright] is an open source end-to-end testing library developed by Microsoft. It works well with Vaadin applications. Its Java API runs your tests in Chromium, Firefox, and WebKit, and its locators find Vaadin components by their role, label, and text, including the parts inside shadow DOM.

Playwright doesn't track when the Vaadin server has processed a request. Instead, its actions and assertions retry until the page reaches the expected state or a timeout passes, which covers the server round-trips of a Vaadin application in most tests. For UI components with a more complex structure, such as [classname]`ComboBox`, [classname]`DatePicker`, and [classname]`Grid`, the <<dramafinder,DramaFinder>> library adds a typed Java API on top of Playwright.

This page describes how to set up Playwright for a Spring Boot-based Vaadin application and how to write a test. In other kinds of applications, only starting and stopping the server differs. For example, you can use the `pre-integration-test` and `post-integration-test` phases, as shown in <<end-to-end/getting-started#,Getting Started with TestBench>>.


== Set Up Playwright

Add the Playwright dependency to your project's [filename]`pom.xml` file:

.`pom.xml`
[source,xml,subs="+attributes"]
----
<dependency>
    <groupId>com.microsoft.playwright</groupId>
    <artifactId>playwright</artifactId>
    <version>{playwright-version}</version> <!-- Check the latest version at https://playwright.dev/java/ -->
    <scope>test</scope>
</dependency>
----

The test on this page also uses [artifactname]`spring-boot-starter-test` to start the application. Add it in the `test` scope unless your project already has it.

Playwright downloads the browsers it needs the first time a test runs.


== First Playwright Test

The test on this page uses the following view:

.`MainView.java`
[source,java]
----
@Route
public class MainView extends VerticalLayout {

    public MainView() {
        var msg = new Paragraph();
        // Add an id to make the element easy to find in a test
        msg.setId("msg");

        var button = new Button("Click me", e -> msg.setText("Clicked!"));

        add(button, msg);
    }
}
----

Add a test class for the view to your test directory, for example [filename]`src/test/java/org/example/`:

.`MainViewTest.java`
[source,java]
----
package org.example;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

import org.junit.jupiter.api.AfterAll;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Tag;
import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.test.context.SpringBootTest.WebEnvironment;
import org.springframework.boot.test.web.server.LocalServerPort;

import com.microsoft.playwright.Browser;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.Playwright;
import com.microsoft.playwright.options.AriaRole;

@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT) // <1>
@Tag("playwright") // <2>
class MainViewTest {

    @LocalServerPort // <3>
    int port;

    static Playwright playwright;
    static Browser browser;
    Page page;

    @BeforeAll
    static void launchBrowser() { // <4>
        playwright = Playwright.create();
        browser = playwright.chromium().launch();
    }

    @AfterAll
    static void closeBrowser() {
        playwright.close();
    }

    @BeforeEach
    void openView() { // <5>
        page = browser.newPage();
        page.navigate("http://localhost:" + port + "/");
    }

    @AfterEach
    void closePage() {
        page.close();
    }

    @Test
    void clickingButtonShowsMessage() {
        page.getByRole(AriaRole.BUTTON,
                new Page.GetByRoleOptions().setName("Click me")).click(); // <6>

        assertThat(page.locator("#msg")).hasText("Clicked!"); // <7>
    }
}
----
<1> Starts the application with a web server on a random port before the tests run. A random port lets the tests run while a development server is running.
<2> End-to-end tests are slower than unit tests. A JUnit tag lets you include or exclude them.
<3> Injects the port that the web server started on.
<4> Launches a headless Chromium once for the test class. Closing the [classname]`Playwright` instance also closes the browser.
<5> Opens a new page for each test, so that the tests don't share browser state.
<6> Finds the button the way a user does, by its role and text, and clicks it. Playwright waits for the button to appear, so the test doesn't need to wait for the view to load.
<7> Playwright's assertions retry until they pass or time out, which gives the server round-trip time to complete. Reading the text with [methodname]`textContent()` and asserting it with JUnit doesn't wait, and can fail if the response hasn't arrived yet.

Prefer the locators that match what a user sees, such as [methodname]`getByRole()`, [methodname]`getByLabel()`, and [methodname]`getByText()`. They also find elements inside the shadow DOM of Vaadin components. See https://playwright.dev/java/docs/locators[Locators] in the Playwright documentation.

== Vaadin Components with DramaFinder

Some Vaadin components take several steps to operate with plain Playwright. Selecting an item in a [classname]`ComboBox`, for example, means opening the overlay, finding the item, and clicking it. https://github.com/parttio/dramafinder[DramaFinder] is an open source library that wraps Vaadin components in typed Java classes for Playwright. Its elements find a component by its label or text, operate it in one call, and wait for the server round-trip. DramaFinder is maintained by the Vaadin community.

Add the dependency next to Playwright:

.`pom.xml`
[source,xml,subs="+attributes"]
----
<dependency>
    <groupId>org.vaadin.addons</groupId>
    <artifactId>dramafinder</artifactId>
    <version>{dramafinder-version}</version> <!-- Check the latest version at https://github.com/parttio/dramafinder -->
    <scope>test</scope>
</dependency>
----

The elements only need a Playwright [classname]`Page`, so they work in a test class set up as above. The following view has a combo box and a date picker:

.`OrderView.java`
[source,java]
----
@Route("order")
public class OrderView extends VerticalLayout {

    public OrderView() {
        var country = new ComboBox<String>("Country");
        country.setItems("Finland", "Germany", "Sweden");

        var delivery = new DatePicker("Delivery date");

        var order = new Button("Order", e -> Notification.show("Delivery to "
                + country.getValue() + " on " + delivery.getValue()));

        add(country, delivery, order);
    }
}
----

A test that opens the `order` route fills in the fields and checks the notification:

.`OrderViewTest.java`
[source,java]
----
import static org.vaadin.addons.dramafinder.element.query.ElementQueries.find; // <1>

@Test
void orderShowsConfirmation() {
    find(page, ComboBoxElement.class).withLabel("Country").single() // <2>
            .selectItem("Germany");
    find(page, DatePickerElement.class).withLabel("Delivery date").single()
            .setValue(LocalDate.of(2030, 1, 15));
    find(page, ButtonElement.class).withText("Order").single().click();

    NotificationElement
            .getByText(page, "Delivery to Germany on 2030-01-15")
            .assertOpen();
}
----
<1> The [methodname]`find()` method is the recommended way to look up a UI component with DramaFinder.
<2> Starts a query for the combo boxes on the page, keeps the one whose visible label is exactly `Country`, and returns it as a typed element. If more than one combo box matches, acting on the element fails the test instead of picking one of them.

The query only offers the filters that fit the UI component, such as [methodname]`withLabel()` for a field and [methodname]`withText()` for a button. Other filters include [methodname]`withAccessibleName()`, [methodname]`withPlaceholder()`, and [methodname]`withTestId()`. To search inside another UI component, such as a dialog, call [methodname]`find()` on its element. The elements also have static shortcuts, such as `ComboBoxElement.getByLabel(page, "Country")`, which run the same lookup.

DramaFinder has elements for most Vaadin components, and base classes that replace the setup code shown above. See the https://parttio.github.io/dramafinder/[DramaFinder documentation].


== Selecting Components with Plain Playwright

Vaadin components are Web Components, so part of their structure lives in shadow DOM and part in slotted light DOM. Without a helper library, a couple of cases trip up hand-written selectors.

=== Dialog Action Buttons Are Slotted

A [classname]`ConfirmDialog`'s confirm, cancel, and reject buttons are *slotted light-DOM children*, not part of its shadow DOM. Target the slotted button directly:

[source,java]
----
page.locator("vaadin-confirm-dialog vaadin-button[slot='confirm-button']").click();
// also: [slot='cancel-button'] and [slot='reject-button']
----

A visibility check based on `offsetParent` skips slotted content and misses these buttons, and synthesizing a `click()` on a guessed wrapper element is unreliable -- especially when a confirm dialog is stacked over another overlay, such as an editor, where you need the real button. See <<{articles}/components/confirm-dialog/styling#,Confirm Dialog styling>> for the full list of slot selectors.

=== Grid Cell Content Is Recycled

[classname]`Grid` renders each cell's content into a `vaadin-grid-cell-content` element and *reuses* these elements as rows scroll or the grid refreshes. Detached copies of previously rendered content can linger in the document, so a broad query such as `document.querySelectorAll('vaadin-grid-cell-content')` may report rows that the user no longer sees.

Read grid state from the *live* cells only -- scope the query to the grid and let Playwright match attached, visible elements -- rather than enumerating every cell-content element in the document:

[source,java]
----
// Matches only attached, visible cell content within the grid
Locator cells = page.locator("vaadin-grid vaadin-grid-cell-content:visible");
----

Alternatively, wait for the refresh to settle (for example, with an explicit `waitFor()`) before asserting, or reload the page to clear detached content.


== Running the Test

Run the test from your IDE, or with Maven:

[source,terminal]
----
mvn test
----

Starting the server and the browser takes a few seconds. To run only the faster tests, exclude the tests that have the `playwright` tag:

[source,terminal]
----
mvn test -DexcludedGroups="playwright"
----

With the commercial TestBench load testing plugin, you can also reuse Playwright tests as load test scenarios, as described in <<load-testing/playwright#,Load Testing With Playwright>>.
