= Set Up the Project

In this section, you'll set up the project that you'll be using throughout this tutorial. When you're done, you have an empty Spring Boot application with Vaadin running on your computer, connected to a database with sample data.


== Prerequisites

You need two things installed on your development machine:

* *A Java Development Kit (JDK), version {vaadin-start-java-version} or newer.* If you don't have one, download and install link:https://adoptium.net/temurin/releases/[Eclipse Temurin] for your operating system. To check which version you have, run `java -version` in a terminal.
* *A Java IDE.* If you don't have one, download and install link:https://www.jetbrains.com/idea/download/[IntelliJ IDEA]. You can use it for free: this tutorial doesn't need a subscription.

Other JDK distributions and IDEs work too. See the <<../dev-environment#,Development Environment>> guide for options.

.Use Hotswap for Faster Development
[TIP]
It is recommended to use hotswap while developing your application. Hotswap reloads changed classes in a running JVM without restarting the application, so you see your changes within seconds. The Vaadin plugin for your IDE sets it up for you. See the instructions for <<../dev-environment/run/intellij#,IntelliJ IDEA>>, <<../dev-environment/run/vscode#,Visual Studio Code>>, <<../dev-environment/run/eclipse#,Eclipse IDE>>, or <<../dev-environment/run/netbeans#,NetBeans>>.


== Create the Project

This tutorial starts from an empty project skeleton. Even if you have completed the <<../quick-start#,Quick Start>>, download a new project here rather than reusing that one, since its code would clash with the code you write in this tutorial.

Click the button below to download a minimal Spring Boot project skeleton with Vaadin:

link:https://start.vaadin.com/skeleton?platformVersion={vaadin-start-platform-version}&javaVersion={vaadin-start-java-version}&groupId=com.example&artifactId=app&frameworks=none&aiTool=NONE[Download Project, role="button primary water", id="docs-tutorial-setup-download-project-cta"]

After downloading the project, unzip it and open the project directory in your IDE. In IntelliJ IDEA, select menu:File[Open], pick the unzipped directory, and click [guibutton]*Trust Project* if asked. For other IDEs, see the import guides for <<../dev-environment/import/vscode#,Visual Studio Code>>, <<../dev-environment/import/eclipse#,Eclipse IDE>>, and <<../dev-environment/import/netbeans#,NetBeans>>.


== Add Dependencies

The application stores its data in an in-memory H2 database. To use the database, you need to add the H2 database and Spring Data JDBC dependencies to your project.

Open the `pom.xml` file in the root of your project and add the following dependencies inside the `<dependencies>` section:
[source,xml]
----
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jdbc</artifactId>
</dependency>
----

Then refresh the project in your IDE to download the new dependencies.


== Create the Database

Spring Boot creates the database when the application starts, using two SQL files: one for the tables, and one for some sample data. Download the following two files and save them in the `src/main/resources` directory of your project, next to `application.properties`:

* link:{articles}/vaadin/tutorial/schema.sql[schema.sql]
* link:{articles}/vaadin/tutorial/data.sql[data.sql]

The `schema.sql` file contains the database schema, and the `data.sql` file contains sample data. Spring Boot automatically executes these files every time the application starts, setting up the database for you.

.The Data Resets on Restart
[NOTE]
Because the database lives in memory, any changes you make in the application disappear when you restart it, and the sample data comes back. This is convenient while you're learning. The <<../next-steps#use-a-real-database,Next Steps>> page tells you how to switch to a real database.


== Run the Application

To make sure everything is set up correctly, run the application. If an application from the Quick Start is still running, stop it first, since both use port 8080. Either start it from your IDE with hotswap enabled, as described in the tip above, or open a terminal in the project directory and run `./mvnw spring-boot:run` (`.\mvnw spring-boot:run` on Windows).

The first startup may take a while as Maven and npm download the required dependencies.


== Check Your Work

Before you continue, verify that your setup matches this list:

* The `<dependencies>` section of `pom.xml` contains the `h2` and `spring-boot-starter-data-jdbc` dependencies.
* The `src/main/resources` directory contains `schema.sql` and `data.sql`, next to `application.properties`.
* The application starts without errors. A log line starting with `Started Application` near the end of the console output confirms that it's running.
* Opening http://localhost:8080 shows a "No views found" page. This is expected: the application has no views yet, and you create the first one in the next step.

If the application fails to start, the console output usually names the cause. An error such as `release version {vaadin-start-java-version} not supported` means that the build uses an older JDK. Check the JDK of your project in your IDE, or the `JAVA_HOME` environment variable if you run the application from a terminal. A compilation error that mentions `org.springframework.data` means a dependency is missing from `pom.xml`. If the SQL files are in the wrong directory, the application still starts, but the view you build in the next step fails with an error about a missing table.
