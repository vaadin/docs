= Building Applications with Spring Boot and Vaadin

This section shows how to build real-world business applications with Spring Boot and Vaadin. Spring Boot runs the application, and Vaadin builds its user interface. Together, they offer multiple ways to achieve results -- some leading to better outcomes than others.

Business applications often start small and evolve over time. While you can figure things out as you go, having a clear roadmap from the start makes the journey smoother. This section of the documentation introduces a structured, opinionated approach to building business applications with Spring Boot and Vaadin. It covers the whole application, not only the user interface, because many of the hardest problems in a business application are in its architecture, data, security, and deployment.

The guides use Spring Boot because it's the easiest platform to start with. Vaadin doesn't require it: you can also build the user interface of a Quarkus application, or of an application on a Jakarta EE server, with Vaadin. See <<{articles}/flow/integrations/quarkus#,Quarkus>> and <<{articles}/flow/integrations/cdi#,CDI>> for how Vaadin works on those platforms.

The guides build the user interface with server-side Flow views, written in Java, unless they say otherwise. To add client-side views written in React, see <<react#,React Views>>.

If you're evaluating Vaadin for a project, start with <<architecture/when-to-use-vaadin#,When to Use Vaadin>>. It describes where Vaadin fits, what its server-side approach costs, and where another tool fits better. Then read <<architecture/runtime-model#,How Vaadin Works at Runtime>>, which is also the place to start if you want to know what happens behind a Flow view. It explains where the UI state lives, what each interaction costs, how threads and sessions work, and what this means for deployment. Finally, see <<architecture/licensing-and-maintenance#,Licensing, Support & Maintenance>> for which features are free and which need a commercial subscription, and how Vaadin versions are maintained.

When your application is ready for real users, the <<production#,Production>> guides show how to build, configure, and deploy it, and how to monitor it.

This section is divided into two main types of articles:

* *How-to Guides* -- Practical, step-by-step instructions for adding features and implementing common tasks.
* *Deep Dives* -- In-depth explorations of key concepts, best practices, and architectural decisions.

== How-to Guides

These hands-on guides show you how to implement specific features or complete essential tasks in your application.

Rather than covering every possible aspect of a topic, the guides focus on the essentials and the most common use cases. They also highlight potential pitfalls and offer practical tips to avoid them.

Many guides include *mini-tutorials* at the end, allowing you to test concepts before applying them to your own applications.

If you're looking for a fast and effective way to become productive with Spring Boot and Vaadin, start with the *How-to Guides*.


== Deep Dives [badge-deep-dive]#Deep Dive#

The Deep Dive articles take a broader and more conceptual approach to building business applications. Unlike the structured how-to guides, these articles explore the reasoning behind certain practices, provide in-depth knowledge, and offer insights, opinions, and alternative approaches.

Reading the Deep Dives isn't essential for getting started. If you're an experienced software developer, you may even disagree with some viewpoints -- and that's perfectly fine. However, if you want to understand the reasoning behind these recommendations and make the most of Spring Boot and Vaadin, these articles are well worth exploring.
