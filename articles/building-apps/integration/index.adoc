= Integration

Your application doesn't need a REST API for its own user interface. Flow views call application services directly on the server, and <<../react#,React views>> call them through browser-callable services. You need a REST API when other systems have to access the data of your application.

<<rest-api#,REST API Alongside Vaadin>> shows how to expose REST endpoints, either from a separate artifact or from the same module as your views. It also shows how to configure security so that the endpoints and the views can coexist.

When your application calls other systems, make the calls from <<../business-logic/add-service#,application services>>. This keeps the integration out of your views, like the rest of the application layer. <<call-remote-services#,Call a Remote Service>> shows how to call a REST service with timeouts and error handling, and what to take into account when passing the access token of the user.


== Messaging

These guides don't cover message brokers, such as Apache Kafka or RabbitMQ. See the https://docs.spring.io/spring-boot/reference/messaging/index.html[Messaging] section of the Spring Boot documentation, which covers both, and the documentation of https://docs.spring.io/spring-kafka/reference/[Spring for Apache Kafka].

A message listener runs in a thread of the messaging client, outside of any user's request. It has no current UI and no Spring Security context, like the background threads described in <<../architecture/runtime-model#threads-and-the-session-lock,Threads and the Session Lock>>. To show the result of a message to users, update a signal or use [methodname]`UI.access()`, as described in <<../server-push/updates#,Pushing UI Updates>>.
