= Licensing, Support & Maintenance

The Vaadin framework and its core components are free and open source under the Apache License 2.0, and you can use them in commercial projects. Some components and tools need a commercial subscription. This page shows which is which, what a subscription means for your builds and servers, and what it takes to keep an application on a maintained version. It doesn't list prices. For those, and for what each subscription includes, see https://vaadin.com/pricing[Pricing].

In this documentation, commercial features have a dollar sign badge in the navigation and on cards, and their pages start with a Commercial Feature notice. You can try them for free in development, as described in <<{articles}/flow/configuration/licenses#using-free-trials,Using Free Trials>>.


== Free & Open Source

The following are free to use in any project, under the Apache License 2.0:

* *The framework*, for both Flow views written in Java and <<{articles}/building-apps/react#,React views>>.
* *The core components*: every component in the <<{articles}/components#,component list>> that doesn't have the dollar sign badge, such as Grid, Combo Box, Date Picker, Form Layout, and Upload.
* *Browserless testing*, which tests your views in Java without a browser. See <<{articles}/building-apps/testing#,Testing>>.
* *The AI integration core*: the orchestrator, the LLM providers, and the component interfaces. See <<{articles}/flow/ai-support#,AI Integration>>.

Two development tools are free to use, but aren't open source, and depend on Vaadin's online services:

* *<<{articles}/tools/copilot#,Copilot>>*, the visual development tool that runs in development mode. Its features that change your code require you to log in with a Vaadin account, and its AI features send source code and prompts to the Copilot server. See the <<{articles}/tools/copilot#privacy,Copilot privacy summary>>.
* *The hosted <<{articles}/building-apps/agentic-development/mcp#,Vaadin MCP server>>*, which gives AI coding agents access to the Vaadin documentation.


== Commercial Features

The following need a commercial subscription:

|===
|Feature |What It Gives You

|Commercial components
|<<{articles}/components/charts#,Charts>>, <<{articles}/components/crud#,CRUD>>, <<{articles}/components/dashboard#,Dashboard>>, <<{articles}/components/grid-pro#,Grid Pro>>, <<{articles}/components/map#,Map>>, <<{articles}/components/rich-text-editor#,Rich Text Editor>>, and <<{articles}/components/spreadsheet#,Spreadsheet>>.

|AI controllers
|Ready-made controllers that let users fill forms and explore data in Grid and Chart with natural language. With the free AI integration core, you can write your own controllers instead. See <<{articles}/flow/ai-support/controllers#,Controllers>>.

|TestBench
|<<{articles}/flow/testing/end-to-end#,End-to-end tests>> in a real browser, with an API for Vaadin components, and a <<{articles}/flow/testing/load-testing#,load testing>> tool that turns browser tests into load tests. |Kubernetes Kit
|Session replication, so that scaling down, a failing server, or a rolling update doesn't lose user sessions. Without it, the sessions on a server that stops are lost, and its users get a reload. See <<runtime-model#what-this-means-for-deployment,What This Means for Deployment>> and <<{articles}/tools/kubernetes#,Kubernetes Kit>>.

|Azure Cloud Kit
|The features of Kubernetes Kit, and templates for deploying to Azure Kubernetes Service. See <<{articles}/tools/azure-cloud#,Azure Cloud Kit>>.

|Observability Kit
|Metrics and traces from the Vaadin runtime, recorded through Micrometer to the monitoring tools you already use. See <<{articles}/tools/observability#,Observability Kit>>.

|Self-hosted MCP server
|The Vaadin MCP server, running inside your own network. See <<{articles}/building-apps/agentic-development/mcp/self-hosting#,Self-Hosting>>.

|Modernization tools
|Tools for modernizing Swing applications and applications built with older Vaadin versions: <<{articles}/tools/modernization-toolkit#,Modernization Toolkit>>, <<{articles}/tools/swing#,Swing Kit>>, and <<{articles}/tools/mpr#,Multiplatform Runtime>>. The analyzers for Maven and Eclipse in Modernization Toolkit are free.
|===

Support for the free features comes from the community, in the https://vaadin.com/forum[Vaadin Forum]. The Pro subscription includes the commercial components and TestBench. The Enterprise Edition adds Kubernetes Kit, Azure Cloud Kit, Observability Kit, the self-hosted MCP server, long-term maintenance, and expert support. See https://vaadin.com/pricing[Pricing] and https://vaadin.com/enterprise[Enterprise Edition] for the current details.

Some tools are deprecated, and you shouldn't use them in a new application:

* *AppSec Kit* and *SSO Kit* aren't included in the next major version. For single sign-on, use <<{articles}/flow/integrations/spring/oauth2#,OAuth2 with Spring Security>> instead.
* *Collaboration Kit* is replaced by <<{articles}/tools/collaboration/migrating-to-signals#,signals>>.
* *Designer* is replaced by Copilot.


== Licenses in Your Build & Runtime

An application that uses only free features needs no license key anywhere. When it uses a commercial feature, licenses affect your environments as follows:

* *Development:* Each developer validates their license with a Vaadin account the first time they use a commercial feature. Machines that can't reach `vaadin.com` need an <<{articles}/flow/configuration/licenses#offline-license-key,offline license key>>.
* *Continuous integration:* Build servers need a <<{articles}/flow/configuration/licenses#server-license-key,server license key>> to make production builds.
* *Production:* A running application doesn't need a license, with two exceptions. If your subscription limits the number of <<{articles}/flow/configuration/licenses/daily-active-users#,daily active users>>, the application needs a subscription key to start, and it reports its daily active users to Vaadin's license server. Extended Maintenance releases check the license key at startup, but only log an error if the check fails.

See <<{articles}/flow/configuration/licenses#,Licenses>> for the details.


== Releases & Upgrades

Vaadin releases a new minor version every three months, and a new major version every one to two years. A minor version adds features, and deprecates old ones without removing them, so upgrading to it is usually a version bump. A major version raises the required versions of Java, Spring Boot, and other technologies, and removes deprecated features, so upgrading to it takes more work.

Free maintenance of a minor version ends one month after the next minor version is released. To keep receiving fixes without a subscription, upgrade to each new minor version as it comes out. After a new major version is released, the one before it receives free maintenance only for a limited time. After that, its fixes need the Enterprise Edition, which maintains each major version for 15 years from its release. See https://vaadin.com/releases[Vaadin Releases] for the current release dates and maintenance periods.

To plan for these, see:

* <<{articles}/compatibility#,Supported Technologies>> for the minimum versions of Java, Spring Boot, Node.js, build tools, application servers, and browsers.
* <<{articles}/upgrading#,Upgrading Guide>> for the changes needed when you upgrade.
* <<{articles}/upgrading/version-comparison#,Version Comparison>> for how the major versions differ.
