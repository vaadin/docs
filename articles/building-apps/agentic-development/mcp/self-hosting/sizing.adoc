= Sizing and Scaling

Measured on a container constrained to one vCPU and 2 GB, serving the full documentation corpus for every bundled Vaadin version:

[cols="2,1"]
|===
|Measurement |Value

|Image size
|About 230 MB

|Cold start to first successful health check
|5 seconds

|Resident memory, model and all indexes open
|291 MB

|Search latency, p50 / p95, two concurrent clients
|8 ms / 42 ms

|Throughput, two concurrent clients
|178 req/s
|===

Treat these as a shape rather than a promise. They come from a natively built arm64 image on Apple Silicon rather than from the amd64 image you deploy, and a 1-vCPU slice on a laptop isn't a 1-vCPU slice on a server, so measure on your own hardware before sizing against them.

One small instance comfortably serves a development team. Nothing in the server holds per-client state -- every request is self-contained, and the transport issues no session -- so if you do need more headroom, run more replicas behind whatever load balancing you already have. There's no shared state to coordinate and no session affinity to configure.
