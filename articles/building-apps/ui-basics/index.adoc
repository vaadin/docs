= UI Basics

These guides cover the building blocks of a Vaadin user interface. You build a user interface as a tree of components. It consists of ready-made components, such as buttons and text fields, layouts that arrange them, and HTML elements for the structure around them.

If you're new to Vaadin, start with <<compose#,Compose with Components>>, which explains how to think in components, and <<layouts#,Arrange with Layouts>>. The other guides each cover a single task, such as showing a notification or handling errors, and you can read them in any order.

To turn your user interface into views that users can navigate between, see <<../views#,Views & Navigation>>. To build reusable components of your own, see <<../components#,Components>>.


== Localization & Accessibility

These guides don't cover translating the user interface, or checking that the application is accessible.

To translate the user interface, see the <<{articles}/flow/i18n#,Localization>> reference. It covers translation files, language selection, the strings of Vaadin components, and number and date formats. To translate the titles of views and the items of the navigation menu, see <<../views/add-navi-menu#translating-titles-and-menu-items,Translating Titles and Menu Items>>.

Vaadin components are designed for compliance with https://vaadin.com/accessibility[WCAG 2.1 level AA]. Whether your application complies depends also on how you use them, for example on labels, headings, and color contrast. Some guides point out what to watch for, such as <<add-images-icons#,Add Images and Icons>> for buttons with only an icon. To check the whole application, see https://www.w3.org/WAI/test-evaluate/[Evaluating Web Accessibility] from the W3C. Automated checkers, such as https://github.com/dequelabs/axe-core[axe-core], find some of the problems, but not all of them.
