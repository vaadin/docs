= Browserless Testing

Browserless tests exercise Flow views and components in the test JVM, without a browser or a servlet container.
Choose the setup that matches your application's dependency injection framework before writing a test.
For the APIs, lifecycle guarantees, and integration details behind these guides, see the <<{articles}/flow/testing/browserless#,Browserless Testing reference>>.

[#choose-your-framework]
== Choose Your Framework

[cols="2,2,2,3"]
|===
| Application | Setup Guide | Maven Artifact | Test Base Class
| Spring Boot
| <<setup-spring-boot#,Set Up Browserless Tests with Spring Boot>>
| `browserless-test-spring`
| `SpringBrowserlessTest` with `@SpringBootTest` and Spring-managed beans.
| Plain Java without a dependency injection container
| <<setup-without-spring#,Set Up Browserless Tests in Plain Java>>
| `browserless-test-junit6`
| `BrowserlessTest`, or a browserless JUnit extension.
| Quarkus
| <<setup-quarkus#,Set Up Browserless Tests with Quarkus>>
| `browserless-test-junit6` and `browserless-test-quarkus`
| `QuarkusBrowserlessTest` with `@QuarkusTest`.
| Java EE / Jakarta EE with Vaadin CDI
| <<setup-cdi#,Set Up Browserless Tests with Java EE/CDI>>
| `browserless-test-junit6`
| `AbstractCdiViewTest`, a base class you add to your tests, with Weld and `CdiVaadinServlet`.
|===

If your project already has UI Unit Testing tests, see <<migrate-ui-unit-tests#,Migrate UI Unit Tests to Browserless Tests>> for which dependencies to replace.

Quarkus has its own integration, even though it also uses CDI.
The Java EE/CDI guide uses the `jakarta.*` packages of current Vaadin applications.

[#use-examples-with-your-framework]
== Use the Examples with Your Framework

The methods that tests use to interact with the UI, such as `navigate()`, `find()`, and `test()`, work the same in every setup.
The setup around them differs, so each test class keeps the base class, dependencies, and configuration from its framework's setup guide.

Most examples in the other guides use the plain Java setup.
To use an example with another framework, change the base class and keep the rest of your setup:

* Spring Boot: extend `SpringBrowserlessTest` and annotate the class with `@SpringBootTest`. Spring beans, Spring test configuration, and Spring Security test annotations apply.
* Quarkus: extend `QuarkusBrowserlessTest` and annotate the class with `@QuarkusTest`. Quarkus test profiles and `@TestSecurity` apply.
* Java EE/CDI: extend `AbstractCdiViewTest`, add the tested view and its beans to its Weld archive, and register the view's route in its setup method.
