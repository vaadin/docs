= Testing

These guides show you how to test the server-side behavior of Flow applications using browserless tests.
Start by <<browserless#choose-your-framework,choosing the setup for your application framework>>, then choose a guide for the behavior you need to verify.

Browserless tests run against Java components without a browser.
Use browser-based tests when you need to verify rendering, client-side behavior, or real browser interactions.
See <<{articles}/flow/testing#comparison,the testing reference>> for a comparison of the approaches.


== Choosing What to Test

Each layer of a Vaadin application is tested in its own way. The following table shows where to find guidance for each:

[cols="2,2,3",options="header"]
|===
|What you test |Kind of test |Guidance

|Application services and their rules, including access control
|Spring integration tests that call the service
|<<{articles}/getting-started/tutorial/add-tests#test-the-service,Test the Service>> in the tutorial, <<../security/protect-services#testing-method-security,Testing Method Security>>, and <<../security/protect-services#testing-record-rules,Testing Record Rules>>

|Queries, migrations, and the database schema
|Integration tests against the same database as in production
|<<../forms-data/persistence/replace-h2#add-testcontainers,Add Testcontainers>>, and https://docs.spring.io/spring-boot/reference/testing/testcontainers.html[Testcontainers] in the Spring Boot documentation

|Flow views
|Browserless tests
|The guides listed below

|Rendering, client-side behavior, and the whole application in a browser
|End-to-end tests
|<<{articles}/flow/testing/end-to-end#,End-to-End Testing>> and <<{articles}/flow/testing/playwright#,Testing with Playwright>>
|===

Service and browserless tests are fast and don't need a browser, so they can cover most of your application. Keep end-to-end tests for what only a browser can show, such as the login flow.

Browserless tests can't test <<../react#,React views>>, because React views run in the browser. Test the browser-callable services of a React view like any other application service, and the view itself with end-to-end tests, or with the JavaScript tools described in <<{articles}/hilla/guides/testing#,Testing>> in the Hilla reference.

To run the tests on every change, see <<../production/ci#,Build on CI>>.
