= Security

Hilla is a combined client and server programming model.
As an application developer, you make a decision about how much of the application state is stored on the server and how much is stored in the user's browser.
The following sections describe the best practices for securing such applications.

ifdef::hilla-lit[]
Security topics that don't depend on the frontend framework are documented only in the main Hilla documentation: <<{articles}/hilla/guides/security/intro#, Introduction>>, <<{articles}/hilla/guides/security/configuring#, Controlling Service Access>>, <<{articles}/hilla/guides/security/authentication#, Accessing Auth Data>>, <<{articles}/hilla/guides/security/offline-auth#, Offline Authentication>>, <<{articles}/hilla/guides/security/spring-stateless#, Stateless Authentication>>, <<{articles}/hilla/guides/security/vulnerabilities#, Common Vulnerabilities>>, and <<{articles}/hilla/guides/security/best-practices#, Best Practices>>. Role-based access control for views is documented for React views in <<{articles}/hilla/guides/routing#, Routing>>.
endif::[]
